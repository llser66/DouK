# DouK 网站操作说明

适用版本：2026-11-02 · 报送进度与回执体验优化版。本文只介绍当前页面；时间均为北京时间。实际每日要求以管理员保存的规则为准，本文中的条数是示例。

## 1. 网站用来做什么

老板通过网站查看员工报送的抖音作品、每日完成数量和未完成情况，处理作者归属异常，并查询作品互动数据。员工无需注册网站账号，但报送前必须核验至少一个有效的抖音账号。

自动巡检已移除，系统不会自动扫描员工抖音主页。员工在平台发布但没有报送的作品，网站不能自动发现。“未完成”表示网站确认的有效作品少于要求，不能直接证明员工没有发布视频。管理员须先建立完整名册，才能看到从未报送的人。

老板端有八个页面：数据总览、数据统计、作品管理、每日报送进度、报送核查、部门与人员、抖音账号管理、系统设置。系统设置仅有报送规则、采集连接、操作日志、访问与备份四项；采集任务入口已移除。

## 2. 打开网站与首次交接

给老板交付时，请先由部署人员完成一次环境安装和局域网配置，再双击项目中的“创建老板桌面入口.cmd”。以后老板每天进入 Windows 桌面，双击“DouK 老板工作台”即可；后台未运行时会尝试启动，失败显示中文提示。项目目录不能随意移动。详见项目根目录的“老板交付说明.md”。

运行项目的电脑称为服务器。服务器开机、进入运行项目的 Windows 用户会话、没有休眠且后台正常运行时，员工才能访问。老板不必一直开着浏览器或保持网站登录；关掉网页不等于停止后台。

- 服务器本机管理员入口：http://127.0.0.1:8877/admin。
- 服务器本机员工入口：http://127.0.0.1:8877/report。
- 员工设备使用服务器局域网地址，例如 http://192.168.9.17:8877/report。这个 IP 只是示例，换电脑或网络后要重新确认。
- 独立采集工具为 http://127.0.0.1:8879，仅服务器本机使用，不在老板工作区内。

在服务器的 DouK-Web 文件夹双击“启动工作台.cmd”；想直接打开员工页可双击“打开员工报送.cmd”，它会先检查并启动后台。打开网页失败时，反复刷新浏览器不会自动修复未启动的后台。

首次安装启动后，管理员账号是 `admin`，初始密码是 `123456`。当前交接站点也已按此设置。已有管理员不会因重启被重置；如果维护人员后来修改了密码，应使用修改后的密码。界面没有自助找回密码功能，忘记密码请联系维护人员。

第一次交接按以下顺序操作：

1. 登录管理员，进入“部门与人员”，补齐所有员工、部门和小组。可手动添加，也可从 Excel 复制名册批量导入。
2. 进入“系统设置 → 报送规则”，保存统一每日条数、执行日、截止时间及生效日期；有特殊要求的人再单独设置。
3. 进入“采集连接”，检查本机服务，并用一条获授权的真实作品验证识别结果。
4. 技术人员配置局域网访问后，在“访问与备份”复制员工地址，并在另一台员工设备上实际打开验证。
5. 告知员工使用一致的部门、小组和姓名，先核验抖音账号，再报送作品。

## 3. 员工报送的完整步骤

1. 打开员工报送地址，不需要网站用户名或密码。
2. 填写部门、小组、姓名，可使用下方已有信息提示。首次成功接收报送时会自动建档；同一人员应保持填写一致，避免产生重复名册。
3. 同部门、同小组有同名人员时，展开工号选项，填写管理员确认的工号。
4. 点击“添加核验账号”，完成官方抖音扫码核验。看到账号显示“已核验”和有效期后再继续；至少一个有效账号是必填条件。
5. 粘贴抖音作品链接、短链接或完整分享文案。一次最多 20 个作品，建议每行一个；不要用账号主页代替作品链接。
6. 点击“提交报送”，服务器接收链接后生成回执，后台再读取作品详情。不要因尚未识别完成反复提交。
7. 在下方“本浏览器的报送回执”查看结果；需要时点击“刷新结果”。
8. 有代报、账号更名或协作等情况，在作品旁点“补充备注”，说明原因并保存，最多 1000 字。管理员能看到备注。

如果已经填好姓名和链接却不能提交，先看账号是否仍在恢复、已过期、被移除或连接中断。未核验、全部过期或全部移除时，页面和后台都会阻止新报送；不是只把“选填”改成文字上的“必填”。

## 4. 多个抖音账号与核验复用

一个人可逐个添加多个账号，不必每次报送切换账号。本浏览器最多保存 100 个核验凭据，每个账号独立有效 7 天；正常刷新、关闭重开和服务器重启后会重新向服务器核实有效性，不会要求每次扫码。使用不会自动延长有效期。

- 作品作者匹配任意一个有效核验账号，且人员、绑定和归属状态允许时，自动登记为已报送。
- 已有有效核验，但作者全部不匹配：接收报送后进入管理员核实，可以补充备注。
- 没有任何有效核验：不能提交新报送。
- 某个账号到期或移除：其余有效账号仍可用。
- 同账号重新核验：更新对应核验，不清空其他账号。
- “取消本次扫码”只取消正在进行的扫码；“移除”需确认，只撤销该核验，不删除平台账号或历史报送。

比对依据是平台稳定标识 sec_uid，不是昵称。昵称相同不代表同一账号。名称暂未读取到时，系统可使用同一账号的历史已保存名称，并提示来源；仍未知时显示昵称未获取。MS4wLj 开头的是平台标识，不是人的姓名。

本站使用独立登录窗口，不能直接读取员工平时 Chrome 或 Edge 中已经登录的抖音账号。因此首次仍可能需要本人扫码。员工核验用于身份比对，不等同于为后台保存采集 Cookie。

同一浏览器、同一网站地址共享核验列表。多人共用电脑换人前应移除原核验；换电脑、浏览器、网址或清理网站数据不会自动同步。账号匹配不能证明视频原创，也不能严格证明填写姓名的人就是实际操作人。

## 5. 回执与处理状态

本浏览器自动显示最近 5 批回执，不是全公司台账。其他员工电脑不会自动看到；同一浏览器共用者可以看到本机回执。

- 等待识别：链接已经保存，等待后台处理。
- 正在识别：后台正在读取，不必重复提交。
- 自动核验通过：作品作者匹配本次有效核验账号，并已形成有效报送记录。
- 人工确认通过：管理员已核实归属并通过；原始作者不匹配结果仍保留，不会被改成“作者匹配”。历史来源无法区分的记录仍显示“已报送”。
- 待管理员核实：作者未匹配、账号归属或状态需要确认；旧版本未核验的历史报送也可能保留在此状态。
- 处理失败：当前无法识别；链接和首次接收时间仍保留，可在管理员端处理。
- 已报送过：作品 ID 已有有效报送，不再增加数量，可能是另一批次已经报送。
- 未通过核实：管理员不接受本次归属，查看说明后联系管理员。

“清除本机回执”只清除本浏览器入口，不删除管理员台账；仅填姓名不能自动找回所有历史回执。管理员实际删除作品后，旧回执刷新时可能被清理，提示“后台不存在”不影响继续报送；重新报送会按新记录处理。

页面打开时自动读取一次回执；等待识别、正在识别时约每 4 秒更新，待核实或处理失败时约每 30 秒更新。切到后台时暂停，回到页面时重新读取，避免一直显示旧审核结果。全部处理完后停止定时刷新，仍可手动点“刷新回执”。“最近更新”是回执读取成功的时间，不是作品发布时间。更新会保留尚未保存的备注和光标；提交备注前请确认内容。

## 6. 老板每天的操作顺序

1. 在“数据总览”看今天的未完成、已完成和无需报送人数。“其中待处理”包含在未完成人数中，不能再相加。
2. 点人数进入“每日报送进度”，查看员工的要求、有效完成、差额和待处理数量。
3. 先处理“报送核查”的待核实与失败记录，防止作品已报送但尚未确认造成差额。
4. 对请假或无报送安排的人记录当日“无需报送”及原因；这不会删除已有作品。
5. 在作品管理查看原作品、统计或导出；在数据统计查看员工、小组的互动表现。

总览的报送待办覆盖全部日期，不受下面作品日期筛选影响。今日完成数、全部待审核数、历史作品总数不是同一个统计范围，数值不同通常不代表出错。

## 7. 每日条数怎样计算

启用每日规则后，有效完成按作品在抖音的发布日期计算，且须已识别、已确认归属并有有效报送。作品 ID 去重，一个作品重复提交不加条数；同一员工多个账号的作品合计。代报经确认后计入作品责任员工，不一定计入粘贴链接的人。

例如要求 3 条，今天发布的作品有 2 条已通过、1 条待核实：显示完成 2/3、还差 1 条、待处理 1 条。第三条通过后变为 3/3。待核实、识别失败、等待识别、未通过不算有效完成；发布时间未知只提示待识别。异常的未来发布时间不会提前计入完成。

补交昨天发布的作品仍归昨天，不抵今天条数。每日截止时间包含该分钟全部秒，例如 18:00 截止包含 18:00:59。截止前不足显示进行中，截止后不足显示未达标。补报可补足原日期的完成数，但保留补报标记；管理员晚审核不会改变首次接收时间。

“未完成”涵盖所有有效完成数量不足的人员，包括有待处理报送的人。进度页默认查看全部未完成；可选择“未完成 · 有待处理”先处理异常，也可选择“未完成 · 无待处理”跟进差额。“其中待处理”是子集，不要把它与未完成再次相加。已驳回的作品不算有效完成，也不再列为待处理。达到要求的人归为已完成，即使还有额外待处理作品，仍应在报送核查查看这些额外记录。

常用日期、部门、姓名/工号、状态直接显示；“更多筛选”里选择小组和具体员工。选择条件后点击“查询”；“重置”返回今天的全部未完成。导出 Excel 使用当前筛选条件。统计规则和名册说明收在人员表下方“如何计算完成情况？”中。

核对范围为所选日结束前已建档、当前启用且未删除的员工。管理员不计入；未绑定账号的在册员工也在范围内。历史日期使用当前组织和启用状态，不是不可变考勤快照。删除有效作品会减少相应日期完成数。

尚未有生效每日规则的日期，页面显示“历史接收记录”，按该日收到的报送统计，不代表该日发布量。不要把旧口径和启用后的有效作品目标混比。

## 8. 统一要求、个人要求与临时安排

在“系统设置 → 报送规则”设置统一条数、每日截止时间、每周执行日和生效日期并保存。条数允许 0–1000，0 表示无需报送。实际规则以页面为准；安装程序不会替老板决定每天几条。

个人长期不同，在每日进度、部门与人员或报送规则中点击个人要求，选从生效日起执行并保存条数。个人常规要求覆盖条数，执行日和截止时间沿用统一规则。多人要求相同可批量选择员工保存。

临时只改一天，选“仅调整指定一天”，填日期、条数及原因。单日可覆盖平时休息日安排；次日按常规规则。恢复继承时选择对应层级并取消此层设置：取消单日后回到个人常规，取消个人常规后回到统一要求。

优先级为：当日“无需报送”记录、个人单日调整、个人常规要求、统一要求。若已有免报记录，即使修改个人条数，当天仍免报；需要恢复时先取消免报。

规则按生效日期保存版本，未来生效设置不会立即改变今天。选择过去日期会影响那天起按规则重新计算的结果；请查看变更记录确认范围。员工报送页不展示统一要求或个人目标，老板端管理这些规则。

每日截止时间和“发布后报送时限”是不同要求。前者判断当日目标补报，后者从单条作品发布时间起算及时报送期限；两者可能给出不同标记。

## 9. 报送核查与紧凑列表

列表分为作品/作者、发布/报送时间、报送人/归属、处理状态和操作。长文案最多两行；点击文案或“详情”看完整内容、全部核验账号、员工备注、处理说明和作者标识。有备注的行显示“有员工备注”，点击直接查看。

每页 30 条，表格内部滚动且表头固定。底部显示总条数和总页数，可翻页。全选仅当前页；翻页后重新选择，不会隐式选中全站记录。

报送日期按服务器接收日期筛选。建议先筛待核实，打开详情核对作者、核验账号、备注和责任人，再操作：

- 审核通过：确认作品记在哪位责任员工名下，可填审核说明。通过不改平台作者和首次接收时间，不把迟交改成按时；已有绑定归属不能在此随意改写。
- 审核不通过：填写原因并确认，保留报送和原因，不计有效完成。
- 重试识别：失败时修复连接或登录条件后重试；批量重试也可处理符合条件的待核实项。重试不是直接通过。
- 批量审核：选择适用记录；不同责任人建议分批。混入不适用状态会禁用相应操作。
- 删除：须管理员确认，删除涉及作品及其所有关联报送，可能包括其他批次；只保留日志，不能在页面恢复。

“已报送”与“作者未匹配”可以同时出现，例如管理员已人工确认代报。前者是最终处理状态，后者保留当时的账号比对事实，并不矛盾。

## 10. 搜索、时间与导出

部门、小组、员工、抖音账号筛选可输入搜索并选择候选；候选显示组织、工号等辅助信息。可以用上下键、回车选择，Esc 收起。实体筛选应选中候选，不能只输入一个不确定名称。

每日进度的“姓名 / 工号”还支持自由关键词查询：点击显示候选，输入缩小范围，选择候选或直接输入关键词再查询。候选会跟随部门、小组和员工条件。

作品管理、数据统计等的发布起止时间可精确到分钟，按北京时间的作品发布时间筛选；截止分钟包含末秒。同一分钟起止也有效。今天报送去年作品，筛“今天发布”不会看到它。

每日进度的“查看作品”按责任员工与作品发布日打开；目标模式下的“查看报送”按报送员工打开且不限定接收日期，便于查看跨日补报；历史接收模式会附带接收日期。代报时两种列表不一定相同。

作品管理和每日进度的 Excel 导出包含当前筛选全部记录，不仅当前页。先核对筛选再导出；无匹配数据时可能提示没有内容可导出。操作日志导出 CSV，访问与备份下载 SQLite，两者用途不同。

## 11. 作品管理与互动统计

作品管理显示封面、文案、作者、责任人、发布/提交时间及播放、点赞、评论、收藏、分享。点击原作品链接可到抖音查看；时间框没有单独彩色底块。

单条“刷新数据”请求平台重新读取详情和统计；刷新网页只是读取本地数据。采集任务页面已移除，但这个刷新功能仍保留。失败时看作品详情中的异常及系统操作日志，检查采集连接后再试。

缺失指标显示暂无数据，不能当成 0；以前成功读取过的值可保留并标记时间意义。排行榜只基于本地可用数据，不能视作平台全量统计。数据总览的已收录作品包括旧版保留记录，可能大于有效报送数量。

## 12. 部门、员工与抖音账号

员工首次报送可自动建档，管理员也可提前添加或批量导入。为监督从未报送的人，必须提前补齐名册。工号用于同名区分；员工不用创建网站密码。

部门与人员页可整理姓名、工号、部门、小组、负责人及启用状态。变更当前分组不自动改写历史作品归属。小组负责人不是全组作品的个人责任人。

抖音账号管理按责任人分组，显示每个人负责几个账号及启用/停用数。可手动绑定主页、调整昵称、责任人和启用状态；匹配报送也可建立绑定。主要显示昵称和 UID，长 sec_uid 用于系统内部匹配，不要求老板手填记忆。

## 13. 删除与停用必须区分

停用保留数据并限制继续使用；删除是真正清除业务记录。所有业务删除都要管理员确认。

- 删除作品或报送：清除关联作品、同作品所有报送、统计、备注和相关刷新任务，日志保留。平台视频不受影响；后来再次报送按新记录处理。
- 删除抖音账号：清除该绑定及关联作品、报送、登录与旧核查数据；员工本人保留。
- 删除员工：清除人员、名下绑定和关联业务，并处理个人规则及负责人引用；不是停用员工。
- 清除本机回执：仅浏览器本地入口，不删除服务器业务。
- 移除核验账号：撤销该浏览器核验凭据，不等于删除管理员绑定或停用平台账号。

删除不能从正常页面恢复，只能由维护人员按备份恢复。正在处理的关联记录可能暂时不允许删除。删除后可以重新建档和报送；明确停用的人员仍须管理员启用，不能靠再次提交绕过。

## 14. 系统设置的四项功能

报送规则：统一和个人每日目标、执行日、生效日期、截止时间；展开附加设置可调发布后报送时限及失败重试。它不会开启作者巡检。

采集连接：本机 API 地址、可选 Token、备用授权 Cookie、保存和连接检查。它供分享解析、作品详情及统计刷新使用，仍有用途。通常本机 API 为 http://127.0.0.1:5555；留空的密码型凭据字段按页面说明保留原配置。“服务已就绪”只证明本机服务能连接，不能保证每条抖音作品可读取。

操作日志：查看识别、审核、删除、名册和规则修改等事件，按关键词、级别筛选并导出 CSV。没有面向老板的清空日志按钮。

访问与备份：复制员工局域网地址，立即备份或下载业务 SQLite。后台运行时按日检查备份，保留最近 14 份；停机期间不会备份。备份包含业务及部分凭据，仅由管理员保管。它不是包含媒体、配置、工具库的一整套项目备份。

采集任务、巡检状态、监测日期和历史补查不再是老板端功能，旧记录保留不表示后台还会继续巡检。

## 15. 发给老板或搬到别的公司

同一局域网员工只需要地址，不用安装项目。服务器可以是老板电脑，也可以是部门专用电脑；只要实际运行后台的机器持续在线即可。

老板与你不在同一局域网时，不能直接使用你电脑的 127.0.0.1 或普通内网地址。可以把干净项目包交给老板，在老板部门的一台电脑安装运行，员工访问那台电脑的局域网地址。这是独立系统，不会自动同步你这里的数据。

若希望不同地点共用同一台服务器，需要另行设计跨网部署。当前交付版没有现成公网 HTTPS、域名或反向代理方案，不能仅发链接或转发端口就当部署完成。具体见开发与部署文档。

迁移原有数据与分发干净安装包是两件事。不要把含 Cookie、员工数据、备份或浏览器资料的 data 目录随意发给别人。

## 16. 常见问题

网页打不开：先在服务器运行启动脚本，确认端口 8877 服务正常；其他设备用服务器局域网地址，确认同网、防火墙和服务器不休眠。

服务已就绪但作品失败：本机 API 可连接与抖音作品可访问不同。检查链接、作品可见性、服务器联网、授权 Cookie 和上游兼容情况；不要通过反复扫码假定能解决所有采集问题。

员工填了信息仍不能提交：至少一个抖音账号须有效且已由服务器确认；待恢复、过期、移除或暂时断连均需先处理。后台也会拒绝无有效核验的请求。

账号已经在日常浏览器登录，仍要扫码：本站独立核验不能自动读取日常浏览器会话；首次扫码后有效期内可以复用。

报送了但没完成今天目标：检查作品发布日期、审核状态、责任人、重复作品、当天适用规则和筛选。补交昨天的作品不计今天。

管理员删过又显示重复：确认删的是服务器作品/报送，而不是仅清除本机回执或移除核验；删除范围内的真实业务清理后允许重新报送。

过去的“读取 0 个发布作品”是什么意思：那是已移除巡检功能留下的历史信息，不能证明没有发布；当前日常管理不使用它。

为什么不能保证查到全部作品：本站接收员工主动报送，不再扫描主页。TikTokDownloader 上游加密算法维护状态及平台变更可能影响读取，网站无法保证平台字段始终可用。
